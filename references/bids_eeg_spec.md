## Filenames and entities

```
sub-<label>/[ses-<label>/]eeg/
    sub-<label>[_ses-<label>]_task-<label>[_acq-<label>][_run-<index>]_eeg.<ext>
```

| Entity | Key | Required for EEG |
|---|---|---|
| Subject | `sub-<label>` | REQUIRED |
| Session | `ses-<label>` | optional |
| Task | `task-<label>` | REQUIRED |
| Acquisition | `acq-<label>` | optional (e.g. different electrode-position recording device) |
| Run | `run-<index>` | optional |

Rules:
- Entities appear in the order above; each entity at most once per filename.
- Labels/indices are **alphanumeric only** -- no underscores, hyphens, spaces. `scripts/inspect_dataset.py --pattern` sanitizes captured values for you.
- `TaskName` in the JSON sidecar and the `task-<label>` filename component can differ: the filename label is the `TaskName` value with all non-alphanumeric characters stripped (e.g. `TaskName: "faces n-back"` -> `task-facesnback`).
- Labels are case-sensitive but must not collide case-insensitively (`sub-s1` and `sub-S1` can't coexist).
- Sidecars for one recording share its stem: `_eeg.json`, `_events.tsv`+`_events.json`, `_channels.tsv`(+`_channels.json`), optionally `_electrodes.tsv`+`_coordsystem.json`.

## Top-level dataset files

**`dataset_description.json`** (root, REQUIRED)
- REQUIRED: `Name`, `BIDSVersion`
- RECOMMENDED: `DatasetType` (raw/derivative/study, default raw), `License`, `Authors`, `GeneratedBy`, `SourceDatasets`, `HEDVersion`
- OPTIONAL: `DatasetLinks`, `Keywords`, `Acknowledgements`, `HowToAcknowledge`, `Funding`, `EthicsApprovals`, `ReferencesAndLinks`, `DatasetDOI`
- Generated by `scripts/write_bids_metadata.py` via `mne_bids.make_dataset_description()`.

**`participants.tsv` + `participants.json`** (root, RECOMMENDED but expected in practice)
- `participant_id` (format `sub-<label>`) REQUIRED, first column, one row per participant.
- Recommended columns: `age`, `sex`, `handedness`, `species`, `strain`, `strain_rrid`.
- Privacy: top-code ages (commonly capped at 89).
- `participants.json` must describe exactly the columns present -- documenting a column the TSV doesn't have is worse than documenting nothing.

**`README`** (root, REQUIRED) -- ASCII/UTF-8, exactly one of `README`/`README.md`/`README.rst`/`README.txt`.
The spec mandates no structure: only that it "SHOULD describe the dataset
in more detail" and stay readable unrendered. It defers to the
bids-starter-kit, which ships no concrete template. So the useful content
is whatever the machine-readable sidecars can't express -- what was
recorded and why, the paradigm, known data-quality issues, the source URL,
and anything you inferred rather than read.

**`CHANGES`** (root, OPTIONAL) -- changelog, ASCII/UTF-8.

**`task-<label>_events.json`** -- task-level metadata sidecar (can live at dataset root and be inherited to every run of that task via the Inheritance Principle). `TaskName` is REQUIRED here whenever a `task-` entity is used.

## `*_eeg.json` sidecar fields

**REQUIRED**: `TaskName`, `EEGReference`, `SamplingFrequency`, `PowerLineFrequency` (or `"n/a"` only if genuinely unknown), `SoftwareFilters` (object, or `"n/a"` if none).

**RECOMMENDED**: `CapManufacturer`, `CapManufacturersModelName`, `EEGChannelCount`, `ECGChannelCount`, `EMGChannelCount`, `EOGChannelCount`, `MiscChannelCount`, `TriggerChannelCount`, `RecordingDuration`, `RecordingType` (continuous/epoched/discontinuous), `EpochLength`, `EEGGround`, `HeadCircumference`, `EEGPlacementScheme`, `HardwareFilters`, `SubjectArtefactDescription`, `Manufacturer`, `ManufacturersModelName`, `SoftwareVersions`, `DeviceSerialNumber`, `TaskDescription`, `Instructions`, `CogAtlasID`, `CogPOID`, `InstitutionName`, `InstitutionAddress`, `InstitutionalDepartmentName`.

**OPTIONAL**: `ElectricalStimulation`, `ElectricalStimulationParameters`.

`write_raw_bids()` auto-fills `SamplingFrequency` and the `*ChannelCount` fields from `raw.info`, and sometimes infers `EEGPlacementScheme` from standard channel names. It CANNOT infer `EEGReference`, `EEGGround`, `Manufacturer`, or `PowerLineFrequency` -- the last one you fix by setting `raw.info["line_freq"]` before writing (see `convert_recording.py --line-freq`); the rest need `scripts/patch_sidecar.py` after writing, using facts from the dataset's own documentation.

## `*_channels.tsv`

REQUIRED columns, in order: `name` (unique), `type` (restricted vocabulary, UPPERCASE), `units` (e.g. `V` -- SI units).

Allowed `type` values: `AUDIO`, `EEG`, `EOG`, `ECG`, `EMG`, `EYEGAZE`, `GSR`, `HEOG`, `MISC`, `PPG`, `PUPIL`, `REF`, `RESP`, `SYSCLOCK`, `TEMP`, `TRIG`, `VEOG`.

Optional columns: `description`, `sampling_frequency`, `reference`, `low_cutoff`, `high_cutoff`, `notch`, `status` (good/bad), `status_description`.

`type` comes from the MNE channel type set via `raw.set_channel_types(...)` before writing (`convert_recording.py --channel-types`) -- not from the channel name.

## `*_events.tsv`

REQUIRED: `onset` (seconds from acquisition start, negative allowed), `duration` (seconds, >=0, `0` = instantaneous event).

Common/recommended: `trial_type` (categorical label -- use this, not `description`), `response_time`, `stim_file`, `value`, `sample`, `HED`, `channel`.

Rules: sort by ascending `onset`; missing values are the literal string `"n/a"`, never blank; document non-obvious columns (especially categorical `trial_type`/`value` codes) in the accompanying `_events.json` via `Levels`.

`convert_recording.py` writes events either from `raw.annotations` (via mne-bids' normal path, `--annotations-only`) or from an explicit CSV (`--events-csv`, written directly) -- never both for the same recording.

## `*_electrodes.tsv` / `*_coordsystem.json`

Only when you have REAL measured/digitized electrode positions -- never for a generic/template cap layout (that misrepresents provenance; use `EEGPlacementScheme` in `eeg.json` instead when you only know the scheme name). If `electrodes.tsv` is written, `coordsystem.json` MUST also be written.

`electrodes.tsv` REQUIRED columns: `name`, `x`, `y`, `z`. Recommended: `type`, `material`, `impedance`.

`coordsystem.json` REQUIRED: `EEGCoordinateSystem`, `EEGCoordinateUnits`. Recommended: `EEGCoordinateSystemDescription`, `FiducialsDescription`, `FiducialsCoordinates`, etc.

`scripts/convert_recording.py --montage <name>` writes both, at write time.

## Allowed raw file formats

RECOMMENDED: **EDF** (`.edf`, lowercase extension only), **BrainVision** (`.vhdr`+`.vmrk`+`.eeg`).
Permitted but discouraged over the above: **EEGLAB** (`.set`[+`.fdt`]), **Biosemi BDF** (`.bdf`).

`write_raw_bids(..., format='auto')` keeps the source format if it's already one of these four; otherwise (GDF, CNT, FIF, custom) it converts to BrainVision. EDF export truncates channel names and clips to a fixed dynamic range -- for long channel names or high-dynamic-range signals, prefer BrainVision as the explicit `--output-format`.

## Derivatives (source-provided preprocessed data)

Some raw exports ship an already-filtered/processed version alongside the
true raw data. That processed version must never be written into the raw
`sub-*/` tree -- and it shouldn't be silently dropped either. If it's
worth keeping, it goes in a
separate `derivatives/<pipeline-name>/` BIDS-derivatives dataset instead.
`scripts/convert_recording.py --desc <label>` and `scripts/write_bids_metadata.py
--dataset-type derivative` handle this; see SKILL.md Step 4b.

Key spec facts (sourced from bids-specification's derivatives pages):
- Directory template: `derivatives/<pipeline-name>/sub-<label>/[ses-<label>/]eeg/<source-entities>[_desc-<label>]_<suffix>.<extension>` -- same entities as the raw file it derives from, plus `desc-<label>` (RECOMMENDED) to distinguish it from the raw version.
- A `dataset_description.json` **MUST** exist at the top of the derivatives folder (`derivatives/<pipeline-name>/dataset_description.json`, not the raw dataset's).
- Unlike raw datasets (where `GeneratedBy` is RECOMMENDED), a derivatives `dataset_description.json` **MUST include `GeneratedBy`**, with `Name` REQUIRED and `Version`/`Description`/`CodeURL`/`Container` RECOMMENDED/OPTIONAL.
- If the derivatives folder is nested inside the raw dataset (`<raw_root>/derivatives/<pipeline-name>/`, the normal case), the first `GeneratedBy` object's `Name` MUST be a substring of `<pipeline-name>` (the folder name).
- `DatasetType` should be `"derivative"`.
- Document the actual processing applied (e.g. filter cutoffs) in the derivative recording's `SoftwareFilters` field (via `patch_sidecar.py`) using facts from the source's own documentation -- not a guess, and not left `"n/a"` if the source tells you exactly what was done.
- The BIDS validator skips `derivatives/` content by default -- run it with `--recursive` (`validate_bids.py --recursive`) whenever a derivatives tree exists, or it will silently pass without ever checking it.
- A derivatives sub-dataset does not need its own `participants.tsv`/`README` -- it inherits those from the parent raw dataset. `write_bids_metadata.py --dataset-type derivative` skips writing them and removes the placeholder versions `write_raw_bids()` auto-bootstraps there.

## BIDS validator

`scripts/validate_bids.py` wraps the `bids-validator-deno` PyPI package (self-contained, installed on demand by `uv run`'s inline dependency block -- no separate Deno/Node setup needed). It exits nonzero only on real errors; warnings are printed but don't fail the run. Always run this as the last step of a conversion, and again after any fix, until zero errors.
